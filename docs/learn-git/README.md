# מפגש 1 — ניהול גרסאות מקומי באמצעות Git

במפגש זה נלמד כיצד להשתמש ב-Git מתוך סביבת הפיתוח Android Studio לניהול גרסאות של פרויקט Android בשפת Java. נתמקד בעבודה של מפתח יחיד: שמירת גרסאות, מעקב אחר שינויים, ביטול שינויים שגויים ושחזור קבצים מגרסאות קודמות.

כל העבודה תתבצע במחשב המקומי, ללא צורך ב-GitHub או בשרת מרוחק.

**משך המפגש:** שעתיים  
**סביבת עבודה:** Android Studio, Java  
**אופן העבודה:** תרגול אישי

## תוכן המפגש

### [0 — הכנת סביבת העבודה](0-setup.md)
ניצור פרויקט Android חדש בשפת Java באמצעות התבנית Empty Views Activity. נכיר את הקבצים המרכזיים בפרויקט, נוודא שתהליך הבנייה מסתיים בהצלחה ונריץ את האפליקציה. בשלב זה לא נבצע שינויים בקוד ולא נשתמש ב-Git.

### [1 — יצירת מאגר Git מקומי](1-repository.md)
ניצור מאגר Git מקומי עבור הפרויקט ונכיר את תיקיית `.git`, שבה נשמר המידע על גרסאות הפרויקט. נבחין בין קובצי המקור לבין קבצים זמניים וקבצים הנוצרים בתהליך הבנייה, ונלמד כיצד להשתמש בקובץ `.gitignore` כדי להגדיר אילו קבצים לא ייכללו בניהול הגרסאות.

### [2 — שמירת גרסאות באמצעות Commit](2-commit.md)
נבצע Commit ראשון של הפרויקט המקורי, לפני שינוי הקוד. לאחר מכן נבצע מספר שינויים בקובצי Java ו-XML, נבחן כיצד Android Studio מזהה קבצים ששונו, וניצור Commits נוספים. נכיר את ההבדל בין שמירת קובץ לבין Commit, ואת האפשרות לבחור אילו שינויים ייכללו בכל גרסה.

### [3 — היסטוריה והשוואת גרסאות](3-history.md)
נשתמש בחלון Git Log כדי לעקוב אחר התפתחות הפרויקט ולראות את רשימת ה-Commits שביצענו. נלמד כיצד לבדוק אילו קבצים השתנו בכל Commit, להשוות בין גרסאות באמצעות Diff ולצפות בתוכן של קובץ כפי שהיה בנקודת זמן קודמת.

### [4 — ביטול שינויים באמצעות Rollback](4-rollback.md)
נבצע שינויים בקוד שעדיין לא נשמרו ב-Commit, ונלמד כיצד לבטל אותם באמצעות Rollback. נתרגל ביטול שינוי בקובץ בודד וביטול מספר שינויים, ונבין מדוע חשוב לבדוק את ההבדלים לפני שמבצעים פעולה שעלולה למחוק עבודה שלא נשמרה.

### [5 — שחזור גרסאות קודמות (Restore)](5-restore.md)
נלמד כיצד לשחזר קובץ מתוך Commit קודם, גם לאחר שבוצעו Commits נוספים. נתרגל צפייה בגרסה ישנה של קובץ, שחזור התוכן שלה לגרסה הנוכחית ושמירת השחזור באמצעות Commit חדש. נבחין בין שחזור קובץ לבין ביטול Commit שלם באמצעות Revert.

### [חלק 6 — סימון גרסאות באמצעות Git Tags](6-tags.md)

**משך משוער:** 5–10 דקות | **רשות**

נלמד כיצד לתת שמות משמעותיים לגרסאות של הפרויקט באמצעות **Git Tags**, במקום להסתמך על מזהי Commit ארוכים (Hash). נתייג את הגרסה הנוכחית בשם `v1.0`, נוסיף Tag ל-Commit קודם, ונראה כיצד ה-Tag נשאר משויך לגרסה שסימנו גם כאשר ממשיכים לפתח ולבצע Commits חדשים. כך נכיר את ההבדל בין Tag קבוע לבין Branch שמתקדם עם הפיתוח.

## מטרות המפגש

בסיום המפגש התלמידים ידעו:

1. ליצור מאגר Git מקומי לפרויקט Android.
2. לבצע Commit ולתעד שינויים בקוד.
3. לבחור אילו קבצים ושינויים לכלול ב-Commit.
4. לבחון את היסטוריית הגרסאות ולהשוות בין Commits.
5. לבטל שינויים שלא נשמרו באמצעות Rollback.
6. לשחזר קובץ מגרסה קודמת.
7. להבין את ההבדל בין Rollback, Restore ו-Revert.

## המפגש הבא — עבודה משותפת באמצעות GitHub

במפגש הבא נעבור מעבודה של מפתח יחיד לעבודה משותפת. נלמד כיצד לפרסם מאגר ב-GitHub, לשתף קוד בין מחשבים ולעבוד על אותו פרויקט עם מפתחים נוספים.

נכיר את הפעולות Clone, Push, Pull, Branch ו-Merge, ונלמד כיצד להשתמש ב-Pull Requests כדי לבדוק ולשלב שינויים של מפתחים אחרים.
