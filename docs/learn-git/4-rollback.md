# חלק 4 — ביטול שינויים באמצעות Rollback

**משך משוער:** 15 דקות  
**סביבת עבודה:** Android Studio, Java  
**דרישות מוקדמות:** פרויקט `GitPractice` מכיל חמישה Commits מהתרגולים הקודמים.

## 4.1 מטרות

בסיום חלק זה נדע:

1. להבחין בין שינויים שנשמרו ב-Commit לבין שינויים שטרם נשמרו.
2. לבטל שינוי בקובץ באמצעות Rollback.
3. לבטל שורות מסוימות בלי לבטל שינויים אחרים באותו קובץ.
4. לבטל שינויים במספר קבצים.
5. להבין מתי Rollback עלול לגרום לאובדן עבודה.

---

## 4.2 נקודות לשיחה — מהו Rollback?

עד עכשיו למדנו כיצד לשמור גרסאות באמצעות Commit וכיצד לחקור את ההיסטוריה שלהן.

אבל מה קורה כאשר אנחנו משנים קוד ומגלים שטעינו?

לדוגמה:

- שינינו הודעה והחלטנו לחזור לטקסט הקודם.
- מחקנו בטעות שורת קוד.
- ביצענו מספר שינויים שאיננו רוצים לשמור.

**Rollback מאפשר לבטל שינויים מקומיים שעדיין לא נשמרו ב-Commit.**

### דוגמה

```text id="r92u8n"
Commit E
   |
   | שינוי בקובץ Java
   v
Working Directory
   |
   | Rollback
   v
Commit E
```

Rollback מחזיר את הקובץ לתוכן שנשמר ב-Commit האחרון, עבור השינויים שבחרנו לבטל.

### Rollback לעומת Commit

| פעולה | תוצאה |
|---|---|
| Commit | שומר את השינויים בהיסטוריה |
| Rollback | מבטל שינויים מקומיים שלא נשמרו ב-Commit |

**חשוב:** Rollback אינו יוצר Commit חדש ואינו מוחק Commits קיימים.

### שאלות לדיון

1. האם אפשר לבטל שינוי שבוצע לפני Commit?
2. האם Rollback מוחק את היסטוריית ה-Commits?
3. מה יקרה אם נבצע Rollback על שינוי שעבדנו עליו שעה ולא שמרנו?
4. האם Git יוכל לשחזר שינוי שמעולם לא נשמר ב-Commit?

## 4.3 משימה ראשונה — ביטול שינוי בקובץ יחיד

**מטרה:** לבצע שינוי בקובץ Java ולאחר מכן לבטל אותו.

### שלב א — שינוי הקוד

1. פתחו את `MainActivity.java`.
2. מצאו את השורה:

   ```java
   Toast.makeText(this, "Welcome to Git Practice - Version 2", Toast.LENGTH_LONG).show();
   ```

3. שנו אותה ל:

   ```java
   Toast.makeText(this, "This is a mistake!", Toast.LENGTH_LONG).show();
   ```

4. פתחו את חלון **Commit**.
5. ודאו ש-`MainActivity.java` מופיע ברשימת הקבצים ששונו.
6. פתחו את חלון Diff ובדקו את השינוי.

**אין לבצע Commit.**

### שלב ב — Rollback

1. בחלון Commit סמנו את `MainActivity.java`.
2. לחצו עליו בכפתור הימני.
3. בחרו **Rollback**.
4. אם מופיע חלון אישור, אשרו את הפעולה.

### בדיקת הצלחה

חזרו ל-`MainActivity.java`.

ההודעה אמורה לחזור ל:

```java id="33d1as"
Toast.makeText(this, "Welcome to Git Practice - Version 2", Toast.LENGTH_LONG).show();
```

ודאו:

- [ ] השינוי השגוי בוטל.
- [ ] הקובץ חזר לגרסה שנשמרה ב-Commit האחרון.
- [ ] אין שינויים ממתינים.
- [ ] לא נוצר Commit חדש.

---

## 4.4 משימה שנייה — ביטול שינוי חלקי בקובץ

**מטרה:** לבטל שינוי אחד תוך שמירה על שינוי אחר באותו קובץ.

### שלב א — ביצוע שני שינויים

1. פתחו את `MainActivity.java`.

2. שנו את הודעת הפתיחה ל:

   ```java
   Toast.makeText(this, "Welcome Back!", Toast.LENGTH_LONG).show();
   ```

3. מצאו את הודעת הלחיצה על הכפתור ושנו אותה ל:

   ```java
   Toast.makeText(this, "Wrong Button Message!", Toast.LENGTH_SHORT).show();
   ```

4. פתחו את חלון Diff של הקובץ.

אתם אמורים לראות שני שינויים.

### שלב ב — ביטול שינוי אחד בלבד

אנחנו רוצים לשמור את השינוי הראשון ולבטל רק את השינוי השני.

1. פתחו את `MainActivity.java` בחלון העריכה.
2. מצאו את השינוי בהודעת הכפתור.
3. לחצו על סימון השינוי בשוליים השמאליים של העורך.
4. בתפריט שנפתח בחרו **Rollback** או את סמל החזרת השינוי, אם הוא מוצג.
5. ודאו שרק השינוי בהודעת הכפתור בוטל.

אם Android Studio אינו מציג אפשרות לביטול שינוי בודד, אפשר לבצע את הפעולה מתוך חלון Diff באמצעות פעולת החזרת השינוי המתאימה.

### תוצאה צפויה

**הודעת הפתיחה נשארת:**

```java id="u7bspt"
Toast.makeText(this, "Welcome Back!", Toast.LENGTH_LONG).show();
```

**הודעת הכפתור חוזרת ל:**

```java id="k7epqw"
Toast.makeText(this, "Button clicked!", Toast.LENGTH_SHORT).show();
```

### שלב ג — שמירת השינוי שנותר

1. פתחו את חלון Commit.
2. ודאו שרק השינוי בהודעת הפתיחה נותר.
3. בצעו Commit עם ההודעה:

   ```text
   Update welcome message to Welcome Back
   ```

### בדיקת הצלחה

- [ ] ביצענו שני שינויים.
- [ ] ביטלנו רק אחד מהם.
- [ ] השינוי השני נשמר.
- [ ] ביצענו Commit רק של השינוי הרצוי.

## 4.5 משימה שלישית — ביטול שינויים במספר קבצים

**מטרה:** לבטל מספר שינויים מקומיים בפעולה אחת.

### שלב א — ביצוע שינויים

1. פתחו את `activity_main.xml`.
2. שנו את טקסט ה-TextView ל:

   ```xml
   android:text="Temporary XML Change"
   ```

3. פתחו את `MainActivity.java`.
4. שנו את הודעת הכפתור ל:

   ```java
   Toast.makeText(this, "Temporary Java Change", Toast.LENGTH_SHORT).show();
   ```

5. פתחו את חלון Commit.

ודאו שמופיעים שני קבצים ששונו:

- `activity_main.xml`
- `MainActivity.java`

**אין לבצע Commit.**

### שלב ב — Rollback למספר קבצים

1. בחלון Commit סמנו את שני הקבצים.
2. לחצו בכפתור הימני.
3. בחרו **Rollback**.
4. אשרו את הפעולה.

### בדיקת הצלחה

- [ ] שני הקבצים חזרו לגרסאות האחרונות שנשמרו.
- [ ] חלון Commit אינו מציג שינויים ממתינים.
- [ ] לא נוצר Commit חדש.

## 4.6 נקודות לשיחה — האם Rollback תמיד בטוח?

Rollback הוא כלי שימושי, אבל יש להשתמש בו בזהירות.

### שינויים שנשמרו ב-Commit

אם השינוי נשמר ב-Commit, Git יכול להציג את הגרסה הקודמת ולאפשר לשחזר אותה.

### שינויים שלא נשמרו ב-Commit

אם ביצענו Rollback על שינוי שלא נשמר ב-Commit, Git עצמו אינו שומר גרסה של השינוי שבוטל.

Android Studio עשוי לאפשר שחזור באמצעות **Local History**, אך אין להסתמך על כך כתחליף ל-Commit.

### שאלות לדיון

1. מדוע חשוב לבדוק Diff לפני Rollback?
2. האם כדאי לבצע Rollback בלי לבדוק אילו קבצים מסומנים?
3. מה ההבדל בין Rollback של קובץ שלם לבין Rollback של שורות מסוימות?
4. מדוע Commit מספק הגנה טובה יותר מפני אובדן שינויים?

- [ ] ביצענו Rollback של מספר קבצים.
