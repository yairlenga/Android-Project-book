# חלק 6 — סימון גרסאות באמצעות Git Tags

**משך משוער:** 5–10 דקות  
**סביבת עבודה:** Android Studio  
**דרישות מוקדמות:** השלמת חלקים 1–5.

## 6.1 מטרות

בסיום חלק זה נדע:

1. להסביר מהו Git Tag.
2. ליצור Tag עם שם משמעותי.
3. לסמן את הגרסה הנוכחית של הפרויקט.
4. לסמן Commit ישן.
5. להבין את ההבדל בין Tag לבין Branch.

---

## 6.2 מהו Git Tag?

לכל Commit ב-Git יש מזהה ייחודי הנקרא **Hash**.

לדוגמה:

```text
a83f21c
```

קשה לזכור מזהים כאלה, ולכן Git מאפשר לתת ל-Commits שמות משמעותיים באמצעות **Tags**.

לדוגמה:

- `v1.0` — גרסה ראשונה של התוכנה.
- `v1.1` — גרסה משופרת.
- `release-2026` — גרסה שהופצה בשנת 2026.

### דוגמה

```text
A ─── B ─── C ─── D ─── E
            ↑           ↑
           v1.0        main
```

ה-Tag בשם `v1.0` מצביע על Commit C.

הענף `main` מצביע על Commit E.

**ההבדל החשוב:**

- **Branch** מתקדם כאשר מבצעים Commits חדשים בענף.
- **Tag** נשאר משויך לאותו Commit.

---

## 6.3 משימה ראשונה — תיוג הגרסה הנוכחית

**מטרה:** לתת שם משמעותי לגרסה הנוכחית של הפרויקט.

### הוראות לתלמיד

1. פתחו את הפרויקט `GitPractice`.
2. ודאו שאין שינויים שטרם נשמרו ב-Commit.
3. פתחו את חלון **Git → Log**.
4. מצאו את ה-Commit האחרון, שעליו מצביע `main`.
5. לחצו עליו בכפתור הימני.
6. בחרו **New Tag** או **Create Tag**.
7. הזינו את שם ה-Tag:

   ```text
   v1.0
   ```

8. אשרו את הפעולה.

### בדיקת הצלחה

בחלון Git Log אמור להופיע `v1.0` לצד ה-Commit האחרון.

```text
A ─── B ─── C ─── D ─── E
                         ↑
                       main
                         ↑
                        v1.0
```

### שאלות

1. האם יצירת Tag יצרה Commit חדש?
2. האם תוכן הפרויקט השתנה?
3. מה ההבדל בין השם `v1.0` לבין ה-Hash של ה-Commit?

---

## 6.4 משימה שנייה — תיוג גרסה קודמת

**מטרה:** להבין שאפשר לתת Tag גם ל-Commit ישן.

### הוראות לתלמיד

1. פתחו את Git Log.
2. מצאו את ה-Commit:

   `Add button with click handler`

3. לחצו עליו בכפתור הימני.
4. בחרו **New Tag**.
5. הזינו:

   ```text
   first-button
   ```

6. אשרו את הפעולה.

### בדיקת הצלחה

ודאו שה-Tag החדש מופיע לצד ה-Commit המתאים.

כעת יש לנו שני Tags:

| Tag | משמעות |
|---|---|
| `first-button` | הגרסה שבה נוסף הכפתור |
| `v1.0` | הגרסה הנוכחית של הפרויקט |

### שאלות

1. האם אפשר ליצור Tag ל-Commit שאינו האחרון?
2. האם אפשר ליצור מספר Tags לאותו Commit?
3. האם יצירת Tag משנה את הקוד?

---

## 6.5 משימה שלישית — מה קורה ל-Tag כאשר ממשיכים לפתח?

**מטרה:** להבין ש-Tag אינו מתקדם יחד עם `main`.

### שלב א — יצירת Commit חדש

1. פתחו את `MainActivity.java`.
2. שנו את הודעת הכפתור ל:

   ```java
   Toast.makeText(this, "New version!", Toast.LENGTH_SHORT).show();
   ```

3. בצעו Commit עם ההודעה:

   ```text
   Update button message for next version
   ```

### שלב ב — בדיקת ההיסטוריה

פתחו את Git Log.

כעת ההיסטוריה אמורה להיראות כך:

```text
A ─── B ─── C ─── D ─── E ─── F
                         ↑     ↑
                        v1.0  main
```

שימו לב:

- `main` התקדם ל-Commit F.
- `v1.0` נשאר על Commit E.

### שאלות

1. מדוע ה-Tag לא עבר ל-Commit החדש?
2. כיצד נוכל למצוא בעתיד את הגרסה שסימנו כ-`v1.0`?
3. מתי כדאי ליצור Tag חדש?

---

- [ ] יצרנו Tag בשם `first-button` ל-Commit ישן.

---

## 6.7 סיכום

| מושג | משמעות |
|---|---|
| Commit | גרסה שמורה של הפרויקט |
| Hash | מזהה ייחודי של Commit |
| Tag | שם משמעותי המצביע על Commit |
| Branch | מצביע המתקדם עם Commits חדשים בענף |

### הכלל החשוב

**Tag מאפשר לתת שם קבוע לגרסה מסוימת של התוכנה.**

בפרויקטים אמיתיים משתמשים ב-Tags כדי לסמן גרסאות ששוחררו, למשל `v1.0`, ‏`v1.1` ו-`v2.0`.

---

### המשך הלימוד

במפגש הבא נלמד כיצד לעבוד עם GitHub, לשתף קוד בין מפתחים ולעבוד עם Branches.
