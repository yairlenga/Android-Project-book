# חלק 1 — יצירת מאגר Git מקומי

**משך משוער:** 15 דקות  
**סביבת עבודה:** Android Studio, Java  
**דרישות מוקדמות:** פרויקט `GitPractice` נוצר בהצלחה, והאפליקציה רצה.

## 1.1 מטרות

בסיום חלק זה נדע:

1. ליצור מאגר Git מקומי בפרויקט Android קיים.
2. להבין היכן Git שומר את המידע שלו.
3. להבחין בין קובצי הפרויקט לבין מאגר Git.
4. לזהות אילו קבצים Git ינהל ואילו קבצים יוחרגו.
5. להבין את תפקידו של הקובץ `.gitignore`.

---

## 1.2 נקודות לשיחה

### מהו מאגר Git מקומי?

מאגר Git ‏(Repository) מאפשר לנהל את היסטוריית הגרסאות של הפרויקט.

- המאגר נמצא במחשב שלנו, בתוך תיקיית הפרויקט.
- אין צורך בחיבור לאינטרנט או בחשבון GitHub.
- Git שומר את היסטוריית הגרסאות בנפרד מקובצי העבודה.
- אפשר להוסיף Git לפרויקט קיים בכל שלב.

### Working Directory לעומת Repository

חשוב להבחין בין שני חלקים:

**Working Directory — תיקיית העבודה**

מכילה את הקבצים שאנחנו עורכים ב-Android Studio, למשל:

- `MainActivity.java`
- `activity_main.xml`
- `strings.xml`
- `AndroidManifest.xml`

**Repository — מאגר הגרסאות**

Git שומר את המידע הפנימי שלו בתיקייה נסתרת בשם `.git`.

התיקייה מכילה, בין היתר:

- גרסאות קודמות של קבצים.
- מידע על Commits.
- מידע על Branches.
- הגדרות המאגר.

בשלב זה המאגר עדיין ריק מהיסטוריית Commits.

### מבנה הפרויקט לאחר יצירת המאגר

```text
GitPractice/
│
├── .git/                  ← מאגר Git המקומי
├── .gitignore             ← הגדרת קבצים להתעלמות
├── .idea/                 ← הגדרות Android Studio
│
├── app/
│   ├── src/
│   │   └── main/
│   │       ├── java/
│   │       │   └── .../
│   │       │       └── MainActivity.java
│   │       ├── res/
│   │       │   └── layout/
│   │       │       └── activity_main.xml
│   │       └── AndroidManifest.xml
│   │
│   └── build.gradle.kts
│
├── gradle/
├── build.gradle.kts
└── settings.gradle.kts
```

**שימו לב:** תיקיית `.git` אינה חלק מקוד האפליקציה. היא משמשת את Git לניהול הגרסאות.

---

## 1.3 משימה — יצירת מאגר Git

ניצור מאגר Git מקומי עבור הפרויקט `GitPractice`.

### הוראות לתלמיד

1. פתחו את הפרויקט `GitPractice` ב-Android Studio.
2. ודאו שהפרויקט נפתח בהצלחה.
3. בתפריט הראשי בחרו:

   **VCS → Create Git Repository**

4. בחלון שנפתח, בחרו את תיקיית השורש של הפרויקט:

   `GitPractice`

   **חשוב:** יש לבחור את תיקיית הפרויקט הראשית, ולא את תיקיית `app`.

5. לחצו **OK**.
6. בדקו ש-Android Studio מזהה כעת את הפרויקט כמאגר Git.

### כיצד נוודא שהמאגר נוצר?

1. פתחו את חלון **Commit** באמצעות סרגל הכלים.
2. בדקו שמופיעה רשימת קבצים שעדיין אינם מנוהלים ב-Git.
3. ודאו שחלון Git זמין ב-Android Studio.

**אין לבצע Commit בשלב זה.**

## 1.4 משימה — איתור תיקיית `.git`

נבדוק היכן Git שומר את המידע שלו.

### הוראות לתלמיד

1. פתחו את חלון **Project** ב-Android Studio.
2. עברו מתצוגת **Android** לתצוגת **Project**.
3. מצאו את תיקיית השורש `GitPractice`.
4. פתחו את התיקייה באמצעות Windows Explorer:
    - לחצו על תיקיית הפרויקט בכפתור הימני.
    - בחרו **Open In → Explorer**.
5. ב-Windows Explorer הפעילו הצגת קבצים מוסתרים:

   **View → Show → Hidden items**

6. מצאו את התיקייה:

   `.git`

7. פתחו אותה ובדקו את תוכנה.

אתם עשויים לראות תיקיות וקבצים כגון:

| שם | תפקיד |
|---|---|
| `objects` | אחסון אובייקטים של Git |
| `refs` | הפניות לענפים ולתגיות |
| `HEAD` | הפניה לענף או ל-Commit הנוכחי |
| `config` | הגדרות המאגר |
| `hooks` | סקריפטים שניתן להפעיל בעקבות פעולות Git |

חלק מהקבצים והתיקיות נוצרים או מתעדכנים רק לאחר ביצוע פעולות נוספות.

**חשוב: אין לשנות או למחוק קבצים בתוך `.git`.**

### שאלות

1. מה ההבדל בין תיקיית הפרויקט לבין תיקיית `.git`?
2. מה יקרה אם נעתיק את הפרויקט יחד עם תיקיית `.git`?
3. מה יקרה אם נעתיק את הפרויקט ללא תיקיית `.git`?

## 1.5 נקודות לשיחה — אילו קבצים Git צריך לנהל?

לא כל הקבצים בתיקיית הפרויקט צריכים להיכלל בניהול הגרסאות.

### קבצים שנרצה לשמור

| סוג | דוגמה | סיבה |
|---|---|---|
| קוד Java | `MainActivity.java` | קוד האפליקציה |
| ממשק משתמש | `activity_main.xml` | הגדרת המסך |
| משאבים | `strings.xml` | טקסטים ומשאבים |
| הגדרות אפליקציה | `AndroidManifest.xml` | תצורת האפליקציה |
| הגדרות בנייה | `build.gradle.kts` | מאפשרות לבנות את הפרויקט |
| Gradle Wrapper | `gradlew`, `gradle/wrapper/` | מאפשר שימוש בגרסת Gradle המתאימה |

### קבצים שבדרך כלל לא נרצה לשמור

| סוג | דוגמה | סיבה |
|---|---|---|
| תוצרי Build | `build/` | נוצרים מחדש |
| מטמון Gradle | `.gradle/` | מידע זמני |
| הגדרות מחשב | `local.properties` | מכיל נתיבים מקומיים |
| קובצי APK שנוצרו | `app-debug.apk` | תוצר של תהליך הבנייה |
| קבצים זמניים | `*.tmp` | אינם חלק מקוד המקור |

**הערה:** חלק מקובצי `.idea` משותפים לפרויקט וניתן לשמור אותם ב-Git, בעוד שאחרים מכילים הגדרות אישיות שיש להחריג.

### שאלות לדיון

1. מדוע לא כדאי לשמור קובצי Build?
2. האם שני תלמידים צריכים להשתמש באותם נתיבים מקומיים של Android SDK?
3. מה היתרון בכך שניתן לבנות את הפרויקט מחדש מקובצי המקור?

## 1.6 משימה — בדיקת `.gitignore`

קובץ `.gitignore` מאפשר להגדיר קבצים ותיקיות ש-Git יתעלם מהם כאשר הם עדיין אינם מנוהלים.

Android Studio יוצר בדרך כלל קובץ כזה כחלק מהפרויקט.

### הוראות לתלמיד

1. חזרו ל-Android Studio.
2. בחלון Project עברו לתצוגת **Project**.
3. מצאו את הקובץ:

   `.gitignore`

4. פתחו אותו.
5. בדקו אילו קבצים ותיקיות מופיעים בו.

דוגמה לתוכן אפשרי:

```gitignore
*.iml
.gradle/
local.properties
.idea/caches/
.idea/workspace.xml
.DS_Store
/build
/captures
.externalNativeBuild
.cxx
```

**שימו לב:** זו דוגמה בלבד. התוכן המדויק תלוי בגרסת Android Studio ובתבנית הפרויקט.

### בדיקת קובצי Build

1. בדקו אם קיימת תיקיית `build` בפרויקט.
2. פתחו את חלון Commit.
3. בדקו אם קבצים מתוך תיקיית `build` מופיעים ברשימת הקבצים החדשים.
4. אם הקבצים מוחרגים כראוי, הם לא אמורים להופיע כקבצים הממתינים להוספה.

### שאלות

1. מה המשמעות של השורה `.gradle/`?
2. מדוע `local.properties` מוחרג?
3. האם `.gitignore` מוחק קבצים מהדיסק?
4. האם הוספת קובץ ל-`.gitignore` מפסיקה אוטומטית מעקב אחר קובץ שכבר נשמר ב-Git?

## 1.8 סיכום

בחלק זה יצרנו מאגר Git מקומי עבור פרויקט Android קיים.

למדנו להבחין בין:

- **Working Directory** — הקבצים שאנחנו עובדים עליהם.
- **Repository** — המידע ש-Git שומר לצורך ניהול גרסאות.
- **`.gitignore`** — הגדרות הקובעות אילו קבצים לא יתווספו אוטומטית למעקב.

בשלב זה Git מוכן לעבודה, אך עדיין לא שמרנו גרסה של הפרויקט.
